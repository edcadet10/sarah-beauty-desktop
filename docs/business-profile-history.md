# Verify private business-profile history

Owners can read a protected current profile or append-only history. No saved profile returns no confirmation. The reader verifies canonical snapshots/hashes, indexed identities and payloads, consecutive revisions, recording-owner membership, TEST/LIVE mode, exact managed-evidence descriptors and agreement between the latest profile and business display name. Historical recording owners can be inactive; their identity stays retained.

Private reasons, legal setup identity and EIN remain excluded from readable projections. A missing physical evidence file does not erase retained metadata; creation and full archives must separately verify the bytes. Replacement files do not change the descriptor pinned to an earlier review.

An archive-source regression first accepted a corrupted private profile. Archive validation now uses the same typed reader for schema 39 and later. Twenty-eight history/profile cases pass, covering the failing-before archive case, canonical/indexed/mode/name mismatches, revision gaps, protected immutable results, inactive historical actors, replaced/missing evidence and forged descriptors, bounded change requests and private export omissions. These cases seed history directly; they do not establish an authenticated save or LIVE setup workflow.
