# Review a changed booking reservation

1. Issue and accept the exact amended quote through **Quotes**.
2. Issue any additional invoice portions and apply actual approved receipts or funded credits to the required trial and booking deposit. Accepting an amendment does not create another payment.
3. Open **Bookings** and reload the section to select the latest booking revision. Save any changed booking fields before reservation review.
4. Expand **Status and history**, enter the review date and decision/evidence, and select **Review changed reservation** with the signed-in owner's passphrase.
5. Expand **Reservation reviews** to verify the original and amended agreements, required amounts, dates, reasons, owners, and times.

The current event, schedule, accepted agreement, and dated trial/deposit funding are checked together. Additional required funding must be approved and applied first. A review cannot precede an earlier recorded confirmation. Repeating the same completed request returns its existing result; the current already-confirmed agreement cannot acquire another duplicate review.

Reviewing a changed agreement keeps the booking Confirmed and appends a reservation review without inventing a second status transition or another cash movement. Both agreement reviews remain available. Unsaved fields block review, and a late result preserves a newer or changed editor.

The fictional demo tool supports `--output NEW_EMPTY_DIRECTORY --reservation-review`. It creates a TEST booking with an original paid reservation and an accepted amendment whose additional deposit is still pending. Complete the actual additional payment/application and reservation review through the app. The tool accepts only a new empty output directory and does not import real business records.
