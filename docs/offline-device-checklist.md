# Check the offline app on the intended devices

These checks remain pending. Development-computer checks do not establish physical Surface operation or recovery on a second computer. Use fictional TEST records and keep passphrases and recovery material private.

## Prepare the Surface

1. Download the [verified Windows preview for source `0a6185b`](https://github.com/edcadet10/sarah-beauty-desktop/actions/runs/43357524913/artifacts/14007271111), or copy its complete extracted folder on removable media. This GitHub artifact expires on November 27, 2026; the [preview workflow](windows-preview.md) can build another copy. It is unsigned.
2. Keep the whole `SarahBeautyDesktop` folder together. No developer tools, Google account, Cloud project, or subscription are needed to run it. Record the Surface model, Windows version, display scale, text size, and available disk space.
3. Disconnect the Surface from Wi-Fi and Ethernet, then open `SarahBeauty.Desktop.exe`. Create a disposable TEST business with two owners and distinct private word passphrases.

## Work while disconnected

1. Using touch, create a fictional customer, expand the optional groups, enter multiline notes, save, and reopen it. Check the missing-contact warning with both contacts blank. Repeat navigation and editing using the keyboard.
2. Create a fictional booking and client document. Generate and open its PDF without reconnecting. Confirm the TEST label, complete text, and readable pages.
3. Save and approve a small fictional financial entry with the selected owner's passphrase. Check its supporting report. Lock, switch owners, close, and reopen the app while still disconnected. Verify the customer, notes, document/PDF, entry, and report remain intact.
4. Check the normal Surface orientation/scaling and a narrow window. Labels and fields must remain readable, controls reachable, scrolling usable, and focus visible with the on-screen and physical keyboards. Record the exact action for any failure.

## Recover on another Windows computer

1. On the Surface, create a protected recovery file and a complete local encrypted archive. Verify the recorded archive. Copy the archive and separately protected recovery material to offline media; retain the passphrase separately.
2. On a second Windows computer, copy the complete app folder and keep networking disconnected. Open archive review from sign-in. An incorrect recovery passphrase must fail clearly; the correct one must validate the database, managed files, counts, and hashes.
3. For the disposable TEST business, retire its previous writable instance through the app before preparing a writable recovered copy. Complete the actual recovery acknowledgment and new-owner-passphrase steps, activate the recovered copy, and restart. Compare the saved records, approvals, reports, PDFs, and permanent IDs with the Surface source. Retained history must match; the recovered writable instance has its own identity. Google reconnection is optional.

Record source commit, device/Windows/scaling, action, expected/actual result, and evidence for each check. Do not mark a result passed until it is performed. [Isolated NTFS out-of-space checks](native-full-volume.md) pass on the development computer. Physical power/hardware failure, clean-machine installer, LIVE facts, and distribution checks remain separate from this device checklist.
