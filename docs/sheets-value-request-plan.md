# Plan bounded literal Sheets value requests

The request planner verifies the readable generation, includes every header and data cell, and produces `values.batchUpdate` JSON with `valueInputOption: RAW`, `majorDimension: ROWS`, and explicit A1 rectangles. All values remain strings, including exact integers, decimals, dates, blank cells, and formula-like text. Google documents [RAW input](https://developers.google.com/workspace/sheets/api/reference/rest/v4/ValueInputOption) as preserving supplied values without parsing.

The planner splits ordinary tables by row and oversized rows by column. It packs rectangles from multiple tables into each request, caps a batch at 100 rectangles, and checks the actual serialized body against a 1,500,000-byte app limit. A conservative range-envelope reserve leaves room for the bounded table name and A1 coordinates; the final serialized-size check remains authoritative. Batches are produced incrementally. Source generation/watermark and frozen expected rectangles accompany each payload for the worker and readback layer.

Google recommends a [2 MB request payload](https://developers.google.com/workspace/sheets/api/limits); that recommendation is separate from the app's local file and decoded generation limits. The 100-range cap is an app choice. It does not claim a Google limit or establish quota compliance. Transport pacing/backoff remains unfinished.

Four new Release cases pass for exact nonoverlapping cell coverage across row/column splits, JSON string types, formula-like text, extreme integers, decimals/dates/Unicode/blanks, actual body sizes, A1 boundaries through DX, range-count limits, cancellation, and all 159 tables from a real fictional capture. A supported maximum row of 128 cells containing 32,768 escaped characters each is split into bounded production requests without truncation.

This is request planning only. No HTTP request or real Google write occurred. Private workbook creation, grid schema, independent typed-cell readback, permission/source fences, durable jobs, completion publication, scheduling, and desktop controls remain unfinished. An HTTP update response alone must not establish readable-generation success. See the [batch update contract](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/batchUpdate) and [value range representation](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values).
