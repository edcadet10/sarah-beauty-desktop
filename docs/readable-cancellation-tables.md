# Project cancellation choices and approved actions

Eight source-bound tables retain current draft/provenance facts, approved decision/hash/provenance, frozen before/after booking facts, approved action/result links, resulting refund journal lines, and separate unapplication, invoice-reduction, and retained/refunded/transferred value choices. `SourceKind` distinguishes the current draft from the immutable approved decision. Never sum both copies as money.

Unknown dates and absent tax-refund allocations stay blank. Explicit zero choices stay zero. Choice amounts are plans; approved actions link the resulting application, document, refund movement, or credit. The resulting journal table repeats existing postings for review; it creates no additional posting and is not another set of books. Status-only cancellation invents no refund or fee. Retained before/after booking names/statuses stay frozen after later edits.

Private decision names, agreement reviews, evidence inputs, client-reason text, and refund-evidence text stay out. Full frozen financial review detail remains in the desktop and encrypted archive. Captured hashes and projected relational identity/date checks protect the retained decision context.

Two fictional cases pass for an actual mixed unapply/credit-note/refund/transfer/retain decision with exact balanced refund journal and later booking edit, and for status-only approval alongside unknown draft dates. This remains a partial projection; no workbook is published.
