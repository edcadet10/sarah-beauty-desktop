# Record a decline, withdrawal, or void for an issued quote

An authenticated owner confirms their phrase and submits an exact quote version/hash, current issued state, dated private reason, and permanent request identity. The writer rechecks current source/state/mode and the decision date, rejects accepted/superseded versions or a booking's accepted binding, and verifies any selected managed evidence bytes. It stores one immutable decision and updates only the cached version state, with one audit/watermark change. It does not cancel the booking, create money, or alter issued contents/PDFs.

Matching retries return the original source-verified decision. A reused request with another payload is rejected. A competing writer cannot replace the first decision. Cancellation, lock, or storage failure after both decision/status writes rolls back the rows, status, audit, and watermark. An earlier accepted agreement and its booking binding remain intact when an unaccepted amendment is withdrawn.

Fifteen related Release cases initially pass across nine new quote cases and six history cases; the added two-handle competing-writer case also passes. Actual fixtures cover all three quote outcomes, unchanged issued hashes and PDF bytes across reopen/retry, no journal posting, one audit, invalid later acceptance/conflicting request, preserved accepted agreement, stale/date/type/foreign rejection, post-write cancellation/lock/storage rollback, changed evidence byte rejection, and original evidence version pinning after replacement. Business Debug has zero warnings/errors. Invoice void rules, recovery/readable verification and desktop controls remain separate work.
