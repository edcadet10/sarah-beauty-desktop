# Activate a verified recovered copy in its own mode

The shared working-store selector carries an explicit TEST/LIVE mode through fresh owner proof, prepared-copy verification, publication, rollback and reopening. The existing TEST interface delegates to this selector. LIVE uses its own pointer and lock; a wrong-mode copy cannot be selected. The candidate catalog also uses the requested mode.

A same-business local primary must be retired using a verified archive covering its current watermark. Retirement checks the store's actual mode. LIVE recovery refuses to replace an unrelated business. Fresh-root recovery still requires the explicit previous-primary acknowledgment recorded during preparation; the app cannot establish another device's physical state.

Clean creation and recovery activation share the LIVE publication lock. An existing selection blocks a new clean business even when no `Primary` folder exists. Failures before the selection commit restore the prior pointer and prepared state. A failure after commit reports that selection succeeded and requires reopening. Exact activation retries require fresh owner proof and preserve the committed watermark. Recovered provenance must match the current mode, store and instance.

LIVE opening resolves a selected recovered copy and validates its business/profile. A verified pre-schema-39 recovery may retain no profile when none was recorded; it opens for explicit setup, with operations still blocked. Once a profile has been recorded, deleting its history cannot use this older-archive exception.

Sixty-five unique related cases pass across the initial activation/creation/opening/mode run and expanded older-schema run. Encrypted LIVE fixtures cover current-primary retirement, readback/retry, new-root selection, interrupted/cancelled/committed publication, unrelated-business rejection and a shared creation lock. A fabricated earlier LIVE archive preserves unknown setup, permits an explicit initial review and rejects later erased history. TEST activation/rollback and older-schema cases continue to pass. Windows Debug and native TEST profile reopen/lock/close pass, preserving the private fixture and managed file.

The full activation regression at source `9439589` passes all 1,503 cases in 6 minutes 57 seconds.
